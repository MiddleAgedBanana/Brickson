# Brickson code audit: correctness and safety against the project's own invariants

> **Research snapshot, 2026-10-15/16, committed 2026-10-21.** Written on the owner's Mac against `main` at `9362eca`; local paths and personal details were removed before it was committed. It is research, not instructions: its recommendations are proposals until `docs/DECISIONS.md` records the owner's choice, and where it disagrees with `AGENTS.md`, `docs/DECISIONS.md` or `docs/ROADMAP.md`, those win. Facts about CI, Xcode and simulator versions describe that date.

Scope: every file under `Brickson/` (App, Home, Library, Speech, Resources) and the tests in `BricksonTests/` and `BricksonUITests/`, read in full at `9362eca` (clean worktree). Read-only; nothing was built or run. Severity uses `.github/skills/code-review/SKILL.md` §5 (High: reachable way to stop communicating / lose words / crash / fail unseen; Medium: real defect under narrower conditions or a broken rule harming no one yet; Low: minor). Each item is marked **[V]** (verified by reading the code path) or **[I]** (inference: a behaviour of Apple's frameworks or a layout estimate I could not confirm without a device or a capture). Gaps that `docs/HANDOFF.md` *Known gaps* or `docs/DECISIONS.md` already record are not re-reported unless I found them worse or wrongly described.

**Headline:** I found no verified High. The first version is careful where it counts: every control is a standard `Button`, every tile speaks on the first activation with no confirm or load step, the audio session is `.playback`, failures surface as passive text, and every save path has a failure-injection test. What remains are three Mediums (one audio-recovery blind spot that depends on an unverified framework behaviour, one wrong message when a person's own library cannot be read, one unrecorded scrolling region on the iPhone), a set of Lows, and a long list of behaviours that exist with no test that could fail.

## 1. Ranked findings

### Medium

**M1. A system-stopped phrase can be recorded as "finished", so no "Stopped — Again" appears.** Invariant 4 ("an interruption keeps the text and names a reachable control to retry"); invariant 5. [V] for the code path, [I] for the trigger.
Path: a long phrase is playing → a call, Siri or a route disconnect stops synthesis before the interruption notice arrives. The code handles that order only when the synthesizer reports `didCancel` (`Brickson/Speech/SpeechService.swift:415-420` → `:232-239` → `SpokenUtteranceTracker.cancelled`, `Brickson/Speech/SpokenUtteranceTracker.swift:96-101`). If it reports `didFinish` instead (`SpeechService.swift:408-413` → `:241`), `utterances.ended(id)` clears the active record, and when the `.began` notice then arrives, `isRepeatableSpeechActive` is already false (`SpeechService.swift:127-131`), so `recordInterruption` is a no-op: the person's sentence stops mid-way, Home shows nothing, VoiceOver hears nothing. Apple's developer forums report `didFinish` being delivered for stopped utterances on iOS 15.5 through 18.1; I could not verify the order or the flavour on iOS 26 (Apple's documentation does not state either). HANDOFF's device table has a row for speech after a call but not for a cut-off *during* one.
Smallest fix within the rules: decide "cut off" from progress, not from which callback arrived. `willSpeakRangeOfSpeechString` already reaches the tracker (`SpeechService.swift:392-406`); have `SpokenUtteranceTracker.began` take the utterance's UTF-16 length, record the end of the last spoken range in `recordProgress`, and let `ended(id)` report "finished short of the end" so `SpeechService.utteranceEnded` treats that as cancelled. It is a pure, `ContinuousClock`-free rule, unit-testable in `SpokenUtteranceTrackerTests`. Add a device check: "incoming call during a 20-word phrase shows Stopped — Again and announces it".

**M2. A library the app cannot read is replaced by the starter phrases with a message about *saving*, so a person whose own words vanish is told the wrong thing.** Invariant 5 (the failure must show the person something true); invariant 7 by consequence. [V]
Path A: the persistent store fails to open (a store written by a newer build, a future migration that fails, a damaged file) → `PhraseLibraryStore.openForApp` catches and returns an in-memory container (`Brickson/Library/PhraseLibraryStore.swift:55-58`) → `PhraseLibraryLaunch.prepare` seeds it with the starter set (`Brickson/Library/StarterLibrary.swift:110-111`) → Home shows Basics/"Hello." and "Phrases can't be saved right now. Changes will be lost when the app closes." (`Brickson/Home/HomeView.swift:332-337`).
Path B: the store opens but the first read fails: `seedIfEmpty`'s `fetchCount` throws (`StarterLibrary.swift:58`) → `prepare` logs "could not be saved" and falls back the same way (`StarterLibrary.swift:112-121`).
In both cases the family sees a stand-in library and a sentence about saving; nothing says their phrases could not be read, that nothing was deleted, or what to do. The obvious family reaction (delete and reinstall) would destroy the intact file. The disk-full case the copy was written for is the one where the store was *empty*, so nobody's words are involved.
Smallest fix: a second `PhraseLibraryIssue` case (`libraryUnreadable`) set from `openForApp`'s catch and from a `seedIfEmpty` read failure (split the read error from the save error), with copy that says the saved phrases could not be read and were not deleted; keep the starter fallback so Emergency still has phrases. Add failure-injection tests for both paths; `openForApp` needs a `makeContainer` seam, which it lacks today.

**M3. On every iPhone in portrait, at the default text size, the category row scrolls sideways and hides categories, with no visible sign.** Invariant 11; design rule "Scrolling is expensive". [I]: estimated from font metrics, not captured.
`CategoryRow` is a horizontal `ScrollView` (`HomeView.swift:216-240`). The four everyday labels at `.headline` (17pt semibold) are about 300pt of text alone; add four icons, `.borderedProminent` padding, 4pt label padding and 36pt of spacing, and the row needs roughly 480–580pt against the 358pt available (390pt width minus 32pt padding). "Feelings" and most of "Conversation" are off-screen; the scroll indicator shows only while scrolling. Touch users may never find Feelings; dwell and switch users pay several activations to reach it. HANDOFF records the *phrase grid* scrolling and the quick-control labels at *larger* sizes; it does not record categories hidden at the default size, and the iPhone is "a first-class device" (`docs/LESSONS.md`, "The phone is a first-class device") that CI never runs. Measure first (AGENTS, "Run it, don't just read it"): iPhone 17 simulator, portrait, default text, light. Smallest fix inside the stand-in: on compact width lay the categories in a fixed two-column grid (size changes with the window; positions do not, which LESSONS "Positions are a pure function of their inputs" allows), or record it in Known gaps and add an iPhone destination to the UI-test job before the layout engine lands.

### Low

**L1. A recycled `ObjectIdentifier` can let a stale callback end or "cut off" the wrong utterance.** [V] for the mechanism, [I] for the timing. Utterances are keyed by `ObjectIdentifier(utterance)` (`SpeechService.swift:277`); only the *current* one is retained (`:70-72`, `:276`), the previous one is released when replaced. Its `didFinish`/`didCancel` is forwarded through an unstructured `Task` (`:422-426`); if that task runs after a new `AVSpeechUtterance` has been allocated at the same address, `utteranceEnded` hits the new utterance: `cancelled(id)` returns true, Home shows "Stopped — Again" while the phrase is in fact playing, and a dwell re-fire is no longer absorbed (a stutter). Fix: keep every in-flight utterance in a set until its end callback arrives, or key the tracker by a monotonically increasing sequence stored in a `[ObjectIdentifier: Int]` map cleared on end.

**L2. Volume warnings have blind spots: no refresh on return to the foreground, and (per Apple forum reports) `outputVolume` KVO only updates while the session is active.** Invariant 4 (visible warnings). [I] The session is configured but not activated until the first phrase (`SpeechService.swift:95-98`, `:355-374`), and `AudioSafetyMonitor` refreshes only on KVO, route change and speech attempts (`Brickson/Speech/AudioSafetyMonitor.swift:36-42`, `:55-62`, `:118-121`). A family lowering the volume while the app is in the background, or before the first phrase, leaves "Volume low" stale (absent or lingering) until the next speech attempt; forum threads also report an initial `outputVolume` of 0 on iOS 18.0, which would show a false "Volume low" at launch and announce it. Fix: call `refreshOutputVolume()` when `scenePhase` becomes `.active`, where `BricksonApp` already observes it (`Brickson/App/BricksonApp.swift:37-39`). Add "volume changed in the background is reflected on return" to the device table.

**L3. When the audio session cannot activate at all, the watchdog turns "Audio failed" into a "Stopped — Again" loop.** [I] `synthesize` still hands the utterance to the synthesizer after activation fails (`SpeechService.swift:271-279`); if the synthesizer then idles with no callback, `watchForMissedFinish` reports a cut-off (`:288-305`), and `.speechStopped` outranks `.audioSessionUnavailable` (`Brickson/Speech/AudioSafetyPolicy.swift:156-169`). The person is told to choose Again, which fails the same way, and the warning alternates between the two texts. Fix: when `audioSafetyMonitor.audioSessionHealthy` is false, let `utteranceEnded(wasCancelled:)` from the watchdog leave the interruption state alone so "Audio failed" stays; a unit test needs the synthesizer seam (section 2).

**L4. The `availableVoicesDidChange` observer is never removed** (`SpeechService.swift:112-118`): the token is discarded, so the block outlives the service. Harmless for the app's single instance (the block captures `self` weakly), but each `SpeechService()` in the unit tests leaks one. Fix: keep the token and remove it in an `isolated deinit`, as `AudioSessionInterruptionObserver` does (`:31-35`).

**L5. `PaletteTests` pins the asset, not the colour tiles actually draw with.** Invariant 6. [V] `Palette.phraseFill` is `Color.accentColor` (`Brickson/Home/Palette.swift:16`), resolved through `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME` (`project.yml:91`); the tests read `UIColor(named: "AccentColor")` (`BricksonTests/PaletteTests.swift:39-46`, `:93-110`). Removing or misspelling that build setting makes phrase tiles system blue (white on #007AFF is about 3.7:1) while every test stays green. Fix: `Palette.phraseFill = Color("AccentColor")`, or a test that `UIView().tintColor` resolves to the asset's value.

**L6. A disabled Emergency control uses the system dimmed look.** Invariant 6. [V] `.disabled(!emergencyIsAvailable)` (`HomeView.swift:185`) fades the white-on-red label, the same failure Again had before `MessageActionButtonStyle` (`:117-145`). Reachable today only with an unreadable starter file; reachable by a person once a category can be deleted. Fix: never let the emergency category be deleted (invariant 2 needs it anyway, and it also settles the re-seeding question, section 3), so the control is never disabled.

**L7. The spoken "Yes."/"No." and the control titles "Yes"/"No" are separate catalog keys** (`HomeView.swift:163,170` vs `:165,172`): a translation can make the spoken word differ from the name Voice Control users say. Fix: derive the spoken text from the button's key plus the sentence terminator.

**L8. Again sits inside the top-right corner margin.** Design rule "Keep corners clear". [V] `HomeView` pads 16pt (`:45`) and `MessageRow` puts Again at the trailing edge of the first row (`:104-112`). The stand-in is accepted, but the layout engine should treat the four corners as keep-out zones for speaking and position-changing controls, not only the top-left recalibration corner.

Not re-reported (already recorded, found as described): the phrase grid scrolling and plain default sizes; no Get Attention; Again beside the message text and the grid above the status text; the selected category's symbol swap shifting neighbours; Personal Voice asked at launch; the session never released; the `fatalError` when no container at all can be made (`PhraseLibraryStore.swift:62`; its message contains no person's words); re-seeding an emptied library; the unlocalized rate names and sample sentence; the untested watchdog and announcements; CI on iPad only.

## 3. Speech engine specifics the brief asked about

- **Session never deactivated** (`SpeechService.swift:355-374`): recorded open decision. One consequence not recorded: after the `.mixWithOthers` fallback during a call (`:366`), the next successful `setCategory` without options (`:358`) restores non-mixable, so the fallback does not stick. Fine. Speech *during* a call reaches only the local route (the far end hears it only through the microphone); phone calls are a core AAC use and are on nobody's list.
- **Watchdog** (`:288-305`): one unstructured task per utterance; stale ones exit within 1 s when the active ID changes, so repeated utterances do not accumulate. It cannot mis-report a phrase that finished normally (the `didFinish` task lands inside the 500 ms grace). It never fires while paused, because `isSpeaking` stays true while paused (Apple's documentation says so; a system pause with no interruption notice therefore leaves "Speaking" on until the person taps something; `absorbsRepeat` checks `isPaused` live, `:253`, so the tap speaks). It cannot tell "never started" from "cut off": implement `didStart`/`didPause` when the seam exists. `try? await Task.sleep` would spin if a task were ever cancelled; nothing cancels them today.
- **Interruption order**: handled for `didCancel`-then-notice and notice-then-`didCancel` (`AudioSafetyPolicyTests.swift:145-165`); not for a `didFinish` flavour (M1).
- **Personal Voice at launch** (`:156-173`): runs in `App.init`; completion is `@Sendable` and hops to main. Recorded decision.
- **`resolveVoice`** (`:311-331`): terminates (each failed descriptor is removed; `select` returns nil only for an empty list) and falls to the system voice. It calls `speechVoices()` synchronously on the speak path when the cache is stale: added latency on the first word, not a correctness issue.
- **UserDefaults** (`:56-61`, `:84-93`): presence check avoids the 0-rate trap; clamp on read; `didSet` does not fire in `init`, so nothing is written at launch. No test covers the keys or the clamp (section 4).
- **Repeat absorption, cases checked**: Emergency phrase under a resting gaze repeats after it finishes (desired); Yes-then-Yes within the ~0.5 s the first is audible is dropped silently (accepted by invariant 10); a paused synthesizer never absorbs (`:253`); stale bookkeeping never absorbs (`SpokenUtteranceTracker.swift:120`); 20 s without progress restarts (`:48`, `:121`). A stutter remains possible only if `isSpeaking` is false in the first milliseconds after `speak()`; documentation says a queued utterance counts as speaking, so I expect not, but a Switch Control double-fire on a device is the check.
- **Media reset "healthy" semantics** (`AudioSafetyMonitor.swift:75-90`, `SpeechService.swift:133-155`): unhealthy until a later `setActive(true)` succeeds; the cut-off phrase is recorded first so Home names Again; tested.
- **Low-volume threshold** 0.2 (`AudioSafetyPolicy.swift:122`) is provisional and the copy says so; volume 0 (fully muted) gets the same informational, low-priority warning as 0.19. Consider an urgent variant at 0.

## 4. Behaviours with no test that could fail

Each with the change that would break it unnoticed.

1. **Interruption during a phrase names Again** through `SpeechService` (`SpeechService.swift:119-132`). Breaks unnoticed if `stop()` moves above the `repeatableSpeechActive` capture. A test can post `AVAudioSession.interruptionNotification` on `NotificationCenter.default` with `object: AVAudioSession.sharedInstance()` and `.began`; no seam needed.
2. **`.mixWithOthers` fallback** (`:361-373`) and **category-set failure → unhealthy** (`:343-350`). Breaks if the fallback is removed or records `succeeded: true` on failure. Needs an `AudioSessioning` seam.
3. **`absorbsRepeat` uses `isPaused`** (`:253`). Breaks if `&& !synthesizer.isPaused` is dropped: a paused sentence would swallow retries. Needs the synthesizer seam.
4. **Watchdog** (`:288-305`): recorded.
5. **`resolveVoice` stale-cache loop** (`:311-331`). Breaks if a failed instantiation falls to `nil` instead of the next voice. Needs a voice-factory seam.
6. **UserDefaults persistence and the rate clamp** (`:56-61`, `:85-93`). Breaks if a key name changes (LESSONS, "Purge removed safety settings"). Test with a `UserDefaults(suiteName:)` injected.
7. **An absorbed repeat does not increment `phraseStartCount` or restart speech** (`:181-188`). `SpeechServiceTests.swift:9-26` calls `stop()` between speaks, so absorption is never exercised.
8. **`openForApp` persistent-open fallback** (`PhraseLibraryStore.swift:46-64`). Breaks if the fallback is removed: a damaged store would crash at launch. Needs a `makeContainer` seam.
9. **`cloudKitDatabase: .none`** (`PhraseLibraryStore.swift:25,52`): a privacy-policy promise with no test. `ModelConfiguration.cloudKitDatabase` is readable; assert it on `container.configurations`.
10. **Phrase tie-break by text then uuid** (`PhraseLibrarySchema.swift:116-122`): only categories are tested (`PhraseLibraryTests.swift:57-72`).
11. **`isIdleTimerDisabled` wiring** (`BricksonApp.swift:37-39`): remove the `.onChange` and nothing fails.
12. **`Text(verbatim:)` for the person's words** (`HomeView.swift:76,224,264`): changing to `Text(phrase.text)` would look the words up in the catalog; a UI test with a phrase equal to a catalog key would catch it, none exists.
13. **Reserved status slot** (`:321-331`): removing the hidden copies moves tiles when a warning appears; no capture-based test.
14. **Off-main boundaries**: only the volume handler is called from a background task (`OffMainThreadCallbackTests.swift:14-30`), and directly, not through KVO (recorded). The Personal Voice completion, the three delegate methods, and the four notification blocks have no off-main test (recorded for the first two).
15. **UI**: Again repeats, category switching, the Emergency check-mark state, anything on an iPhone, any accessibility text size, dark mode: none is driven.

## 6. Localization and resources

- `Brickson/Resources/Localizable.xcstrings` has zero strings. With `LOCALIZATION_PREFERS_STRING_CATALOGS` and `SWIFT_EMIT_LOC_STRINGS` (`project.yml:44-45`) Xcode fills the catalog during builds, but the file on `main` has never changed since `a1f8cfa`, so either `scripts/test.sh` builds do not write it back or nobody staged it. In practice: every `String(localized:)` and `LocalizedStringKey` falls back to its key, so English is unaffected; no translation can start; nothing reviews the words in one place; no test asserts the catalog covers every key. `SpeechRateSteps.description` returns "Normal" / "N% of normal" in English in every locale (`Brickson/Speech/SpeechRateSteps.swift:25-28`) and `previewSample` is English (`SpeechService.swift:192`): both recorded. Cross-string dependency: "Stopped — Again" (`AudioSafetyPolicy.swift:61`) must name the button exactly as the catalog names it; `compactMessage.contains("Again")` pins English only. Next step: the owner builds once in Xcode, commits the populated catalog, and a unit test parses the JSON and checks every known key is present.
- Asset catalog: three universal opaque fills, pinned (`PaletteTests.swift:93-110`); no dark variants by design. App icon: 1024×1024 8-bit RGB PNG without alpha (App Store requires no alpha); placeholder recorded; the new artwork in `design/brand/` is not in the catalog yet.
- `PrivacyInfo.xcprivacy`: UserDefaults CA92.1, no tracking, no collection; pinned. Backup (file timestamps, disk space) will need new reasons when built.
- `Info.plist` is generated from `project.yml`; `AppBundleTests` reads the bundled file, so `~ipad` keys are checked on any simulator. `UIBackgroundModes: audio` with no silent audio: recorded App Review note.
- `StarterPhrases.json`: 34 phrases, neutral; passes the invariant-7 reading. "Please ask me yes or no questions." is a communication-strategy phrase many people choose; I would keep it. The two near-duplicates and "Please move me." are already on the owner's list.

## 7. Structural notes before the next features land

1. **Put a protocol over `AVSpeechSynthesizer` (and one over the session) before the Get Attention port.** The alarm shares the session and the warning slot; the watchdog, pause/finish semantics (M1, L3), absorption with `isPaused`, and the alarm's start/stop ordering all need deterministic tests that `SpeechService` cannot host today (`ensurePlaybackAudioSession` is already `internal` for the alarm, `SpeechService.swift:355`).
2. **One owner for the audio session.** Decide the open "release after speech" question together with the alarm; a release while the alarm sounds, or a category change by one caller that clears the other's options, is the kind of fight two owners have.
3. **Build the tile-action resolver now, with today's three cases.** Invariant 2 says one pure resolver owns speak-vs-edit and every tap path goes through it; today tiles, Yes, No and Emergency call the service directly (`HomeView.swift:163,170,177,262`). Introducing it before edit mode means edit mode arrives as one more input, tested in both orders of every mode change (LESSONS, "One resolver per safety decision").
4. **There is no Stop.** Short starter phrases hide it; typed messages will not. Reserve the Stop slot in the layout engine now, in a different place from Speak, never in a keyboard toolbar.
5. **SwiftData before editing:** disable the main context's autosave (`container.mainContext.autosaveEnabled`, default on) so every save is explicit and failure-injectable; implement category delete with its phrase deletes in one save; decide what happens to phrases left with `category == nil` by `.nullify` (`PhraseLibrarySchema.swift:42-43,65`): they are invisible on Home and must never be deleted by a repair. Make the emergency category undeletable, which also removes the re-seeding question (an emptied store cannot occur).
6. **Decide provenance before V1 ships.** The seeder cannot tell starter phrases from a person's own words later; a future opt-in "add the new starter phrases" needs either a stored origin field in V1 or acceptance that it can only append. LESSONS says fields arrive with their feature; the counterweight is that V1 is what every later version migrates from.
7. **Launch path.** `App.init` opens the store, seeds, lists voices and requests authorization synchronously (`BricksonApp.swift:16-26`, `SpeechService.swift:80-157`).
