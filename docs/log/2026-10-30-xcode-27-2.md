# Xcode 27.2: the Mac moved, CI follows by itself

*2026-10-30. Pull request #68 (`claude/project-thread-5nl90x`). Thread
"Move the build to Xcode 27.2", a cloud session with a read-only check on
the owner's Mac.*

## What changed and why

The owner installed Xcode 27.2 and asked which of its two iOS 27.2
simulator runtimes, 24B91016s and 24B8117, is for iPhone Duo. The Mac
answered it (*Verified*): **24B91016s holds only iPhone Duo; 24B8117 holds
every other iPhone and iPad.** Both are needed.

The rule (docs/DECISIONS.md, "Build with Apple's current Xcode") is that
the build moves to Apple's newest release in a pull request that also
fixes anything the new Xcode reports. Nothing in the repository names an
Xcode, so the move is not an edit to a version number:

- **Apple.** Xcode 27.2 is the current release: the Mac App Store listed
  Version 27.2 on 2026-10-30 ("6h ago"), and Apple's system requirements
  page lists Xcode 27.2 with Swift 6.4, the iOS 27.2 SDK and macOS Tahoe
  26.6 or later. Its build is 27B52 (`xcodebuild -version` on the owner's
  Mac; xcodereleases.com dates it 2026-10-29). Apple's releases feed,
  read 2026-10-30 at about 06:20 UTC, still listed only the release
  candidate, Xcode 27.2 RC (27B48, 2026-10-19), though it listed iOS
  27.2 (24B119, and 24B91020 for other devices) on 2026-10-26.
- **CI.** GitHub's `xcode-27` image (20261026.0314.1, its published
  software list) holds 27.2's release candidate, 27B48, in
  `Xcode_27.2_Release_Candidate.app` with `Xcode_27.2.app` linked to it,
  and 27.1 as its default. The release is a different build, so
  `scripts/select-xcode.py` keeps CI on 27.1, the newest release that
  machine has, and moves by itself once GitHub installs 27B52 and Apple's
  feed lists it; `check` warns on every run in between once the feed
  does. Its iOS simulator runtimes are 27.0, for every device but Duo,
  and 27.1, for Duo only. No workflow change is needed, so none is handed
  to the owner. Two tests pin this case in `scripts/test-select-xcode.py`.
  docs/DECISIONS.md, "Build with Apple's current Xcode", records why CI
  does not build with the candidate meanwhile.
- **Language mode.** Apple's system requirements page lists Swift 6 as
  the newest language mode in Xcode 27.2, so `SWIFT_VERSION: "6.0"` in
  `project.yml` stays.
- **A bug the new runtime found.** Xcode 27.2 gives iPhone Duo a runtime
  whose identifier names the device after the version,
  `com.apple.CoreSimulator.SimRuntime.iOS-27-2-iPhone19-4`. On 27.1 the
  Duo's runtime was plain `iOS-27-1`. `scripts/choose-simulator.py` read
  only plain identifiers, so it dropped every simulator on the Duo
  runtime, and the documented way to run the UI tests on a Duo simulator
  (AGENTS.md, *Gotchas*: `DESTINATION='platform=iOS Simulator,id=<udid>'
  scripts/test.sh ui`) stopped with "No available iOS simulator has the
  id …" before building. The chooser now reads a device suffix after the
  version, and the default iPad and iPhone choices are unchanged.

Documents that said something now untrue were edited: docs/HANDOFF.md
(CI's runtimes, where CI stands, the Mac check, and the JSON trial's
timing), docs/DECISIONS.md (the JSON format's "Why not now", and two
bullets of "Build with Apple's current Xcode"), docs/APP-STORE.md (which
SDK builds Brickson), AGENTS.md (a gotcha about the Duo runtime) and
docs/GETTING_STARTED.md (the two runtimes, for someone setting up a Mac).

**The JSON project format trial is not unblocked yet.** The owner's
2026-10-25 handoff set the trial after Xcode 27.2 *and* its first fix
release (docs/DECISIONS.md, "Xcode's JSON project format", its step 1).
The first half is met; the trial starts when 27.2.1 or 27.3 is released.
This pull request neither runs it nor replaces XcodeGen.
