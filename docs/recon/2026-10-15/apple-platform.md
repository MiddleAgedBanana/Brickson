## 2. Five platform moves with the highest payoff

1. **Speak into phone and FaceTime calls (microphone injection), iOS 18.2+.** API: `AVAudioApplication.shared.microphoneInjectionPermission`, `requestMicrophoneInjectionPermission()`, `AVAudioSession.sharedInstance().setPreferredMicrophoneInjectionMode(.spokenAudio)`, `microphoneInjectionCapabilitiesChangeNotification`, `AccessibilitySettings.openSettings(for: .allowAppsToAddAudioToCalls)`, `NSMicrophoneInjectionUsageDescription`. 2. **Personal Voice lifecycle done end to end, iOS 17/18+.** Keep the ask-before-first-synthesis order (`SpeechService.swift:156`, now backed by forum 764814); on `scenePhase == .active` re-read `AVSpeechSynthesizer.personalVoiceAuthorizationStatus` and `refreshVoices()`; when `.denied` show a Settings row that calls `AccessibilitySettings.openSettings(for: .personalVoiceAllowAppsToRequestToUse)`; when `.unsupported` say so in plain words; never route Personal Voice through `write(_:toBufferCallback:)`. Invariants: 2, 4, 5 (every status has visible text), 6. Test: a pure `PersonalVoiceGuidance(status:hasPersonalVoice:)` resolver with a case per status (fails if `.denied` stops naming the Settings path); an `OffMainThreadCallbackTests` case that invokes the authorization completion from a detached task (closes the HANDOFF gap). 3. **Typing that never hides the call for help.** API: `ignoresSafeArea(.keyboard)` on Home so nothing reflows; a single-line `TextField` with `submitLabel(.send)` + `onSubmit` (Return speaks; `TextEditor` never submits); `GCKeyboard.coalesced != nil` to pick the hardware-keyboard bar height versus the measured full keyboard; `keyboardWillShowNotification` frames converted to the window's coordinate space to re-measure per OS release. 4. **Lock the device to Brickson safely: Assistive Access full-screen key plus Guided Access guidance, iOS 17+.** API: `UISupportsFullScreenInAssistiveAccess = YES` in `project.yml` `info` (Brickson keeps its measured layout and runs full screen above the system Back button; it is listed as Optimized); do not adopt the iOS 26 `AssistiveAccess` scene (it restyles and re-lays out controls). ## 3. Risks

1. **`interruptionNotification` is deprecated from iOS 27** (`SpeechService.swift:20`). Still valid at the 26.0 target, but the owner builds with Xcode 27 / iOS 27 and Apple says new code should adopt the life-cycle notifications because the legacy signal "get[s] out of sync when the system can't deliver an end event", which is exactly the problem the comment at `:122-125` works around. Move 5.
2. **`.spokenAudio` mode is for podcast-like apps** (`SpeechService.swift:345,358,366`): Apple documents it as "pause, rather than duck, its audio if another app plays a spoken audio prompt". A navigation prompt or Siri can therefore pause the person's sentence by design. Not a contradiction, but a choice the code does not record; decide with move 5.
3. **The session is never deactivated** (`setActive(false)` is never called) while nonmixable: Apple asks nonmixable apps to deactivate when idle in the background; otherwise the system deactivates it on suspension and delivers a delayed `.began` with `AVAudioSessionInterruptionWasSuspendedKey = true` on resume. The observer at `:9-36` ignores that key and calls `stop()` + `recordInterruption(repeatableSpeechActive:)`; verify `SpeechInterruptionStatus` records nothing when nothing was speaking, and read the key. Also the known gap that other apps' audio never resumes.
4. **Personal Voice in the background and in `write()`** (forum only, no Apple statement): the review-notes demonstration "choose a long phrase, then lock the device: speech continues" (DECISIONS "Background audio") may fail in a Personal Voice; the planned recorded-phrases export cannot render Personal Voice. Device check before any claim.
5. **Delegate threading is undocumented**; the code's hop is correct, but the Personal Voice completion and the synthesizer delegate have no off-main tests (HANDOFF gap) and `OffMainThreadCallbackTests` exercises only the volume handler.
6. **`outputVolume` may be stale after backgrounding** (forum 813242): refresh in `AudioSafetyMonitor` on `scenePhase == .active`, not only on route change/activation (`AudioSafetyMonitor.swift:57,118`).
7. **iOS 26 button rendering:** bordered buttons are capsules by default; Quick controls (`HomeView.swift:188`) and categories (`:239`) set no `buttonBorderShape`, so their shape and tap area changed with iOS 26 (phrase tiles at `:279` set one). Whether `.borderedProminent`'s fill is fully opaque under Liquid Glass is not documented; `PaletteTests` measure asset hex values, not rendered pixels. Add a rendered-pixel contrast check (XCUIScreenshot sampling) in light, dark, Increase Contrast and Reduce Transparency. Apple also recommends an increased-contrast variant per colour asset; the three assets have single values.
8. **iOS 27 resizing versus the portrait-only iPhone decision** (DECISIONS "Orientations", `Info.plist:40-42`): TN3192 lists "Supports all interface orientations" among the requirements for resizable scenes, WWDC26 278 says orientation "will be ignored when your app is running in a resizable environment" (iPhone apps on iPad and iPhone Mirroring), and a beta console warning says all-orientation support "will soon be required". Invariant 11 must now hold at arbitrary window sizes on iPhone-class layouts too. The launch-screen requirement (TN3208) is already met by `UILaunchScreen`.
9. **App Shortcuts privacy rule** (AGENTS "App Shortcut phrases and parameters never contain phrase words"): achievable only with fixed phrases and no `AppEntity` parameter in App Shortcuts, because Apple may extract phrases and entity display representations for training; the privacy policy's Siri section currently promises something looser ("lets iOS see the words of your phrases"). Decide before building.
10. **Microphone injection category unknown:** the sample's audio-session category is not in the doc text. Apple's `setActive` doc says a `.playback` session may activate during a call; `.playAndRecord` fails with `insufficientPriority`. Device check with Brickson's `.playback` + `.mixWithOthers` fallback.
11. **`canOpenSettings(for:)` is iOS 26.4+** while the target is 26.0; `openSettings` throws (guard and show passive text).
12. **`isolated deinit`** defers destruction when the last release happens off the main actor; harmless for observer removal, but don't move anything time-critical into those deinits.
13. Nothing in the documentation contradicts `SpeechService.swift` or `AudioSafetyMonitor.swift` as written for iOS 26: `stopSpeaking(at: .immediate)` on an idle synthesizer, re-creating the synthesizer after a media-services reset, deferring activation to the next user action, and the `.mixWithOthers` fallback all match Apple's text.
