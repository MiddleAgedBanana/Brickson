## What changed and why

The owner asked how Xcode 27.2's new JSON project format affects
Brickson, whether it was planned for, and to plan for it. It was only a
one-line follow-up in [`2026-10-21-toolchain.md`](2026-10-21-toolchain.md)
("worth weighing against XcodeGen when it is released"), with no trigger
and no owner. This pull request makes it a plan, in documents only:

- docs/DECISIONS.md, "Xcode's JSON project format" (new, beside
  "Generated Xcode project", and a row in the register of defaults):
  XcodeGen stays for now; a trial on the owner's Mac once Xcode 27.2 is
  released; the gates the switch waits for; what the switching pull
  request changes; and what the format fixes and does not fix for
  Brickson.
- docs/ROADMAP.md, *Held on purpose*: the format, held until Apple
  releases Xcode 27.2.
- docs/HANDOFF.md, *Next steps, in order*: one sentence, edited in place
  where the toolchain's follow-ups are named.
- AGENTS.md, *Gotchas*: never commit a project file, and never move the
  build to JSON outside that plan.

In short: the format is Apple's fix for `project.pbxproj`, the file that
causes merge conflicts and unreadable diffs when a project is committed.
Brickson never commits its project (XcodeGen writes a fresh one from
`project.yml` on every run), so it does not have that problem today, and
nothing breaks when 27.2 ships: Xcode 27 reads both formats, existing
projects are not converted by themselves, and XcodeGen keeps writing the
old one. What the format could give Brickson is Apple's own project file
in place of a third-party generator, with Xcode's editor usable again.
Converting a generated project costs the same at any time, so the plan
waits for a released Xcode, a clean trial and one round of fixes.

## Sources

Read on 2026-10-25:

- Apple: [Xcode 27.2 RC release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-27_2-release-notes)
  (*Project Format*), [Updating your Xcode project configuration file
  format](https://developer.apple.com/documentation/xcode/updating-your-xcode-project-configuration-file-format)
  (availability: Xcode 27.2 and later), and the [releases
  feed](https://developer.apple.com/news/releases/): Xcode 27.1 (27A9275,
  2026-10-15) is the newest release; 27.2 RC (27B48) came on 2026-10-19.
- Apple's [xcode-project-format](https://github.com/apple/xcode-project-format)
  at `0a7242a` (tag 0.1.0; first commit 2026-09-16) and its
  [documentation](https://swiftpackageindex.com/apple/xcode-project-format/0.1.0/documentation/xcodeprojectformat):
  the format's goals, the schema (synchronized folders, exception sets,
  `required-capabilities`), the `xcprojformatter` tool, and the decoder,
  which reads comments and drops them (`Sources/Library/Serialization/Decoder.swift`,
  `KeyedContainer`). Read only; nothing from it was run.
- Outside sources, because Apple does not cover other tools: tuist's
  XcodeProj documentation (`Documentation/json-project-format.md`:
  "experimental"; what a conversion drops), Tuist's changelog of
  2026-09-17 (says earlier Xcode versions cannot read the format, which
  Apple contradicts), XcodeGen's releases (2.46.0 is the latest and
  writes `project.pbxproj` only) and its issue #1655 (open, unanswered).
